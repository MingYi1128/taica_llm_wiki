Big O 是什麼？

描述「輸入變大時，執行時間（或空間）成長得多快」

  • 只看成長趨勢，忽略常數：3n 與 100n 都是 O(n)
  • 只是上界：f(n) ≤ c·g(n)，當 n ≥ n₀
  • O 來自德文 Ordnung（階、order）
Wiki：big-o

三個容易搞混的符號

符號意思
O（Big O）上界
Ω（Big Omega）下界
Θ（Big Theta）上下界夾住（tight bound）

⚠️ 我們課堂的 little o 定義是「極限 = 1」，和一般教科書（極限 = 0）不同，考試依老師版本。

常見誤解：Big O ≠ 最壞情況。「最壞情況」是挑輸入，「Big O」是函數的界。

二元搜尋：想法

  1. 先確認陣列已排序
  2. 拿目標 X 和中間元素 aⱼ 比
  3. X = aⱼ → 找到；X < aⱼ → 只看左半；X > aⱼ → 只看右半
  4. 重複，直到找到或範圍變空
i := 1; m := n
while i <= m do
   j := ⌊(i+m)/2⌋
   if X = a_j then output j and stop
   if X < a_j then m := j-1 else i := j+1
output 0

  • 穩定（相同值不換順序）

Wiki：selection-sort

快速排序：分而治之（概念）

  1. 選一個 pivot
  2. 分成「比 pivot 小」與「比 pivot 大」兩堆
  3. 兩堆各自遞迴排序
  • 平均 O(n log n)，最壞 O(n²)
  • pivot 的選法影響效能，不影響正確性

本次期中不考，這裡只建立概念。

Wiki：quicksort

四種演算法對照

演算法最好最壞備註
二元搜尋O(1)O(log n)需已排序
插入排序O(n)O(n²)穩定、近排序時快
選擇排序O(n²)O(n²)與資料無關
快速排序平均 O(n log n)O(n²)pivot 很關鍵

插入、選擇排序的次數依課堂定義：分別是資料搬移數與比較數。

小測驗（點題目看答案）

Q1：在 255 筆已排序資料用二元搜尋，最多比較幾次？

⌊lg 255⌋ + 1 = 8 次。

Q2：選擇排序排 10 個數，比較幾次？

10×9/2 = 45 次，不管資料長怎樣。

Q3：對 [5, 2, 9] 做二元搜尋可以嗎？

不行，必須先排序。

回顧與來源

  • Big O = 成長趨勢的上界
  • 二元搜尋：已排序 + 每次砍半 → O(log n)
  • 排序：插入（近排序快）、選擇（次數固定）、快速（平均快）
